# 팀 자료 기억 봇 — 서비스 기획서

「8조 솔루션 AI — 인터뷰 인사이트 & 기능 제안서」(2026-11-16)를 구현 가능한 수준으로 구체화한 문서다.
제안서의 결정(A+B안, 디스코드 중심·카톡 보조, 핵심 차별점은 공유 의도와 버전 계보)을 그대로 따른다.

## 1. 한 줄 정의

디스코드에 설치만 하면, 팀원은 **하던 대로 올리고** 봇이 읽고 정리하며, 찾을 때는 **대화 중에 `/찾아줘`** 한 번으로 찾아 채널에 공유한다.

- 대상: 작업이 갈라지고 자료가 반복 수정되는 3~5인 초기 팀
- 해결하는 문제: 디스코드 검색 실패, 버전 혼동, 공유 의도 손실 (재탐색 1회 최대 20분)
- 하지 않는 것: 원본 이동·삭제, 담당자 지정, 주간 정리 요구, 태그 입력 강제

## 2. 설계 원칙과 구현 방식

| 원칙 (제안서) | 구현에서 지키는 방법 |
|---|---|
| 사용자 추가 행동 0, 입력은 선택 | 파일·링크가 올라오면 자동 처리. 확신하면 📌 반응만 남기고, 애매할 때만 버튼을 띄운다. 버튼을 안 눌러도 AI 값으로 저장된다. |
| 설치만 하면 됨, 규칙은 말로 수정 | `/용어 등록`, `/규칙 등록`으로 등록한 문장을 AI가 분류·검색 때마다 읽는다. 규칙이 바뀌어도 코드는 그대로다. |
| 원본은 절대 이동·삭제하지 않음 | 봇은 사본만 만든다. 봇에 메시지 관리 권한을 주지 않는다. 사람이 고친 내용은 모두 `audit_log`에 남는다. |
| 기존 AI 작업 흐름으로 연결 | 자료 사본을 구글 드라이브 폴더에 올리고 「팀 자료 목록」 시트를 유지한다. 이 폴더를 ChatGPT·Gemini·Claude에 연결하면 메신저를 다시 뒤질 필요가 없다. |

## 3. 사용 흐름

### 3.1 공유 시점 (올릴 땐 하던 대로)

1. 팀원이 채널에 PDF나 링크를 올린다. 태그는 필요 없다.
2. 봇이 사본을 아카이브 폴더에 저장하고, 본문과 직전 대화 몇 줄을 읽어 제목·요약·주제 태그·공유 의도를 만든다.
3. 결과에 따라 봇의 반응이 달라진다.

| 상황 | 봇의 반응 |
|---|---|
| 의도를 확신 (확신도 ≥ 0.75) | 원문에 📌 반응만 |
| 의도가 애매 | 답글 1개 + 버튼 4개(레퍼런스 / 경쟁사 / 피드백 요청 / 제출용). AI 추측이 강조 표시된다. 안 누르면 그대로 두고 10분 뒤 답글을 지운다. |
| 주제 태그가 애매 | 같은 답글에 태그 선택 메뉴(최대 3개). AI가 붙인 태그가 미리 선택돼 있다. 의도와 태그 중 애매한 것만 묻는다. |
| 비슷한 이전 자료가 있음 | "「○○」의 v2로 연결했어요. 바뀐 점: …" + [맞아요, 새 버전] [별개 자료예요] |
| 이미 보관된 자료를 다시 올림 | ♻️ 반응만 (재업로드 횟수는 지표로 센다) |
| 밈·잡담 사진 | 아무 반응 없음 (AI가 읽어 보고 업무 자료가 아니면 보관하지 않는다) |

답글은 알림 없이(silent) 보내고, 확인이 끝나면 한 줄로 줄였다가 지운다. 알림 피로를 줄이기 위해서다.

### 3.2 검색 시점 (찾을 땐 대화 중에 바로)

1. `/찾아줘 질문:본선용 IR 자료` — 채널을 몰라도, 띄어쓰기가 달라도 된다.
2. 봇이 "찾는 중"을 먼저 표시하고(디스코드 3초 제한), 결과 최대 5건을 **본인에게만** 보여 준다.
   각 결과에 제목, 공유 의도, 버전, 맞는 이유, 원문 메시지 링크가 붙는다. 최신본이 아니면 경고한다.
3. [n번 채널에 공유] 버튼을 누르면 채널에 공개 메시지로 올라간다.

### 3.3 팀 용어·규칙

서버에서 처음 쓸 때 기본 규칙 3개(주제 태그 기준, 공유 의도 기준, "올린 사람이 말로 밝힌 의도가 우선")가 들어간다. 팀은 `/규칙 목록`에서 보고 지우거나 바꿀 수 있고, 한 번 지운 기본 규칙은 다시 들어가지 않는다.

- `/용어 등록 내용:경쟁사조사=벤치마킹` → "벤치마킹"으로 찾아도 "경쟁사조사" 자료가 나온다.
- `/규칙 등록 내용:리서치 자료는 제목 앞에 [리서치]` → 이후 올라오는 자료의 제목·태그에 반영된다.

### 3.4 카카오톡 (보조 입구)

단톡방을 읽는 공식 API가 없으므로, 카톡의 "대화 내보내기" 텍스트 파일을 `/카톡가져오기`에 올리면
그 안의 링크를 같은 아카이브에 넣는다. 내보내기 파일에는 첨부파일이 들어 있지 않아 링크만 가져온다.
카카오 챗봇(1:1 전달)은 이번 범위에 넣지 않았다(8절 참고).

| `/내보내기` | 모두 | 자료 목록 CSV |

## 5. 시스템 구성

```
디스코드 ──(메시지·명령·버튼)──▶ bot.py ──▶ service.py ─┬─▶ extract.py  PDF·DOCX·PPTX·XLSX·HWP·HWPX·링크 본문 추출
                                                        ├─▶ llm.py      Gemini(기본)·Claude: 분류·버전 판단·검색 재정렬, OCR
                                                        ├─▶ search.py   글자 2-gram 어휘 검색, 버전 후보 탐지
                                                        ├─▶ db.py       SQLite (자료·용어·규칙·수정 기록·이벤트·설정)
                                                        ├─▶ ARCHIVE_DIR 로컬 사본 + INDEX.md + index.csv
                                                        └─▶ gdrive.py   구글 드라이브 사본 + 「팀 자료 목록」 시트 ──▶ AI 연결
카톡 내보내기(.txt) ──▶ kakao.py ──▶ service.py
```

- **AI**: Gemini API(무료 등급 사용 가능)가 기본이고, 설정으로 Claude로 바꿀 수 있다. 무료 등급은 요청 수 한도가 있어 한도를 넘으면 간이 분류·글자 검색으로 대신한다.
- **분류**: 자료 1건당 AI 호출 1회. 구조화 출력으로 제목·요약·태그·의도·확신도·이전 버전 id·바뀐 점을 한 번에 받는다.
- **버전 후보**: 파일명에서 `v2`, `최종`, `수정3차`, `본선용`, 날짜 같은 표기를 떼고 비교하거나 본문 겹침으로 후보를 최대 5건 뽑아 AI에게 넘긴다. AI가 후보 밖의 자료를 고르면 무시한다.
- **검색**: 띄어쓰기를 무시한 글자 2-gram으로 후보를 뽑고(용어 사전으로 질문 확장), AI가 목록에서 뜻이 맞는 자료를 고른다. 자료가 60건 이하면 전체 목록을 보여 줘 표현이 전혀 달라도 찾는다.
- **본문 추출**: DOCX·PPTX(표·발표자 노트)·XLSX·HWPX(XML)·HWP 5.0(바이너리 레코드)은 봇이 직접 읽는다. 옛 형식(DOC·PPT·XLS)과 암호·배포용 HWP는 파일명과 맥락으로만 분류한다.
- **OCR**: 쪽당 글자가 30자 미만인 PDF는 스캔본으로 보고 앞 20쪽을 AI에 PDF 그대로 보낸다. 이미지는 긴 변 1568px로 줄여 보낸다. AI는 분류와 함께 읽은 글자의 핵심(최대 1500자)을 돌려주고, 이것이 검색용 본문이 된다. 별도 OCR 엔진을 설치하지 않아도 되고 한글 인식이 좋다.
- **이미지 거르기**: 채팅 이미지는 대부분 밈·잡담이므로, AI가 업무 자료(표·슬라이드·문서·시안 캡처)라고 판단한 것만 보관한다. API 키가 없으면 이미지를 아예 보관하지 않는다.
- **API 장애·키 없음**: 키워드 기반 간이 분류로 내려간다. 이때는 확신도가 낮아 모든 자료에 확인 버튼이 뜬다.
- **저장**: 제안서의 "로컬 CSV로 시작" 대신 SQLite를 쓰고 CSV는 `/내보내기`와 `index.csv`로 제공한다. 버전 연결과 수정 기록을 CSV로 관리하면 동시 수정에서 깨지기 쉽기 때문이다.
- **드라이브·시트**: 자료를 보관하면 5초 정도 모았다가 서버별 드라이브 폴더에 사본을 올리고 「팀 자료 목록」 시트를 다시 쓴다. 의도·버전·제목이 바뀌어도 시트를 다시 쓴다. 업로드에 실패한 자료는 10분마다 다시 시도하고, 폴더가 지워졌으면 새로 만든다. 인증은 개인 계정 OAuth(`drive.file` 권한: 봇이 만든 파일만 접근)와 공유 드라이브용 서비스 계정 둘 다 지원한다. 시트는 봇이 덮어쓰는 읽기 전용 목록이며, 수정은 `/수정`으로 한다.

## 6. 데이터 구조

| 테이블 | 주요 필드 | 용도 |
|---|---|---|
| `documents` | 제목, 요약, 태그, `intent`/`ai_intent`/`confidence`/`intent_source`, `version_group_id`/`version_no`/`version_label`/`change_note`, 원문 링크, 사본 경로, `drive_file_id`/`drive_url`, `sha256`, `reuse_count` | 자료 1건 = 1행 |
| `settings` | 서버, 키, 값 | 서버별 드라이브 폴더·시트 ID |
| `glossary` | 용어, 뜻 | 팀 용어 사전 |
| `rules` | 규칙 문장 | 팀 정리 규칙 |
| `channel_settings` | 채널, 수집 여부 | 채널별 수집 끄기 |
| `audit_log` | 누가, 무엇을, 이전 값, 새 값, 시각 | 모든 수정 기록 (책임 소재) |
| `events` | `search` / `share` / `rerequest` / `reshare`, 소요 시간 | 지표 계산 (메시지 본문은 저장하지 않음) |

버전 계보는 `version_group_id`(첫 버전의 id)와 `version_no`로 표현한다. 연결을 끊으면 자기 자신이 새 계보의 v1이 된다.

## 7. 검증 지표와 측정 방법

`/통계`가 아래 값을 계산한다. 도입 전 값은 인터뷰의 AS-IS 데이터를 기준선으로 쓴다.

| 지표 (제안자) | 봇이 재는 방법 |
|---|---|
| 재요청·누락 자료 수 (2) | "다시 올려줘", "어디 있어?" 류 메시지 수 + 같은 자료 재업로드 수 ÷ 보관 자료 수. 문구 매칭으로 횟수만 세고 본문은 저장하지 않는다. |
| AI 태그 수정률 (2) | 사람이 AI와 다른 의도로 고친 자료 수 ÷ 보관 자료 수 |
| 검색 소요 시간 (3) | `/찾아줘` 실행부터 공유 버튼 클릭까지의 중앙값 |
| 아카이브 재사용률 (3) | `/찾아줘` 횟수, 한 번 이상 공유된 자료의 비율 |
| 만족도 (1) | 봇 밖에서 도입 전후 설문 |

## 8. 개인정보·권한

- 봇은 **파일이나 링크가 있는 메시지**만 처리한다. 그 외 메시지는 재요청 문구 매칭 외에는 읽지 않고, 저장하지 않는다.
- 분류할 때 직전 메시지 3개(설정 가능, 0이면 끔)를 맥락으로 AI API에 보낸다. 이 맥락은 저장하지 않는다.
- Gemini 무료 등급에 보낸 내용은 Google 약관상 서비스 개선에 쓰일 수 있다. 민감한 채널은 수집을 끄거나 결제 등급을 쓴다.
- 자료 본문과 맥락(스캔 PDF·이미지는 원본)이 외부 AI API로 전송되므로 **설치 전 팀원 동의**가 필요하다. 민감한 채널은 `/수집 끄기`로 제외한다.
- 밈·잡담 사진은 AI가 한 번 읽지만 저장하지 않는다.
- 구글 연동 토큰은 봇이 만든 파일에만 접근하는 최소 권한으로 받는다.
- 봇에 필요한 권한: 채널 보기, 메시지 보내기, 메시지 기록 보기, 반응 추가, 파일 첨부. 메시지 관리 권한은 주지 않는다.
- 채팅에 올라온 링크를 서버가 대신 열기 때문에 사설·로컬 주소 요청은 차단한다.

## 9. 범위

| 구분 | 이번 구현 | 이후 |
|---|---|---|
| 입력 | 디스코드 파일(PDF·DOCX·PPTX·XLSX·HWP·HWPX 본문 추출, 스캔 PDF·이미지 OCR), 링크, 카톡 내보내기 링크 | 옛 형식(DOC·PPT·XLS) 본문, PPTX 안 이미지 OCR, 카카오 챗봇 1:1 전달 |
| 분류 | 공유 의도 4종, 주제 태그 고정 목록 + 팀 규칙 | 팀별 의도 종류 추가 |
